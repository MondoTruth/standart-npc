# Ragnarok Offline: управление персонажем при проверке квестов

Эта заметка нужна, чтобы повторять проверенный процесс и не повторять ошибки прогона Abyss Chaser.

## Основной инструмент

Использовать `scripts/rotest.cjs` из `ragnarokoffline.app` и NPC-helper `standart-npc/tests/play-helper.js`.

- `rotest start`, `login`, `char 0`: запуск клиента и вход персонажем.
- `rotest state`: карта, класс, координаты, NPC и монстры рядом.
- `rotest gm "<команда>"`: GM-команда.
- `rotest walk <x> <y>`: обычная ходьба по клику клиента.
- `rotest stop`: остановка тестового клиента.
- `rotest world down`: остановка изолированного мира.

NPC-helper внедрять после каждого перезапуска клиента. Диалоги проходить через `snpc.talk`, `snpc.view`, `snpc.next`, `snpc.choose`, `snpc.close`.

## Важные правила

- После `rotest stop` подождать завершения; если `start` сразу сообщает `already: true`, повторить запуск после остановки старого процесса.
- После полного перезапуска мира снова выполнить `login`, `char 0` и внедрение helper.
- Не использовать `@reloadscript` для временного мода: NPC мода могут исчезнуть. Полностью перезапускать мир через `world down/up`.
- В `snpc.view()` финальная страница может одновременно иметь `next: true` и `close: true`. Сначала проверять `close`, затем `next`, иначе диалог может остаться открытым и заблокировать следующий шаг.
- Не разговаривать со следующим NPC, пока предыдущий скрипт с `sleep2`/`npctalk` не завершился. Для дерева Abyss Chaser ждать не меньше 3 секунд после закрытия диалога.
- При ошибке диалога смотреть текущее `snpc.view()`, `state` и журнал map-сервера, а не считать автоматически виноватым квест.

## ID профессий и GM-команды

Проверять числовые ID в исходнике, не полагаться на память или отображение клиента.

- Shadow Chaser: `4072` (`JOB_SHADOW_CHASER`), не `4073`.
- Abyss Chaser: `4260` (`JOB_ABYSS_CHASER`), не `4261`.

```text
@jobchange 4072
@baselvl 198
@joblvl 69
@allskill
```

`@baselvl` и `@joblvl` ПРИБАВЛЯЮТ уровни, а не устанавливают абсолютное значение. С Base 1 команда `@baselvl 198` даёт Base 199; `@baselvl 199` даст Base 200. Нельзя проверить понижение Base 200 до 199 или Job 70 до 69 этими командами. Для граничных случаев начинать с нужного меньшего уровня или отдельно подготавливать изолированного персонажа через SQL с остановкой сервера и резервной копией.

`@allskill` выполнять после установки нужного Job Level.

## Инстансы

Не использовать `@warp 1@4sac ...` для перемещения внутри Abyssal Mansion: это исходная карта, а не созданный инстанс. На исходной карте `instance_id()` равен 0, переменные инстанса недоступны, NPC ведут себя неправильно.

В тестовом мире внутреннее имя карты видно в журнале, например `1032#000002`. Для тестовых телепортов использовать именно его:

```text
@warp 1032#000002 79 51
```

Обычный `rotest walk` ограничен видимой областью и проекцией камеры: дальняя клетка может быть off-screen, а клик может попасть в соседнюю клетку. Проверять результат каждого `walk`, не считать отсутствие исключения успешным перемещением.

## Бой

- `@nuke` без имени не работает, а `@nuke Tester` бьёт персонажа, а не монстров.
- Для завершения проверки босса использовать `@killmonster2 <внутреннее имя карты инстанса>`.
- Убедиться, что сработал `On...Dead`: NPC должны сообщить о победе и открыть следующий шаг.
- В обработчике смерти монстра нет прикреплённого игрока: не использовать там `sleep2`.

## Проверка результата

Проверять не только диалоги:

- класс через `state`;
- карту и координаты после входа/выхода;
- награду через игровое сообщение и, после сохранения, SQL;
- финальный quest ID и состояние в таблице `quest`;
- журнал map-сервера на новые ошибки скриптов.

Тестовые ошибки драйвера отделять от ошибок квеста. Полный прогон повторять после изменения игровой логики; если повтор не выполнен, прямо сообщать об этом.
